Remove Redis completely from crowdsec-bouncer-traefik-plugin to simplify the library. CrowdSec LAPI stream cursor is per hashed X-Api-Key + outbound IP LAPI sees (pod IP), not per API key alone. Evidence: knowledge/research/ext_crowdsec_lapi_stream-cursor/ and https://github.com/crowdsecurity/crowdsec/issues/3726 (LaurenceJJones: two remediations on one key+row steal stream deltas; LAPI creates name@IP rows so each replica is an independent stream). This plugin's Redis CachePrefix is SessionHex (LAPI URL+key only) and handleStreamCache skips LAPI when cache key "updated" exists — replicas share one dump and skip their own poll, which contradicts LAPI. Prefixing Redis by pod IP would be remote-per-pod memory with no sharing benefit. Decision: delete redisCacheEnabled and the entire Redis/Dragonfly/simpleredis cache path. Each process keeps stream and live decisions in its isolated in-memory map. In-process warn-and-wire (one ticker, same outbound IP) stays. Write why in spec/devdocs. Do not keep Redis for live mode. Captcha grace is already the HMAC cookie, not cache. Out of scope: changing CrowdSec LAPI identity (issue 3726), captcha gate redesign, AppSec.
