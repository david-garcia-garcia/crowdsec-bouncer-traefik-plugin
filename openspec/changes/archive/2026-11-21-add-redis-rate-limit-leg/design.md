## Context

See proposal.md for why. Measured on this worktree (dest `master` @ `44e2151b`):

- `ServeHTTP` runs trusted skip → `foldActionRules` (ban returns) → `serveLAPI` → `serveAppSec` → `next` (`pkg/bouncer/bouncer.go`). Each `serve*` returns true when it wrote the response.
- Legs are reclaim values opened in `plugin.New` on `bindCtx` (`openOwned`) and late-bound through `Watch` + `atomic.Value` because they can be published under an instance name. The rate limiter is not published (requirement Out of scope), so it needs only the Open half.
- `bouncer.New` has 109 callers (mostly tests). Its signature does not change in this design.
- `httprule.New` rejects a row whose every predicate is "any" (`compileRule` → `empty`). Buckets need that row to mean "every request".
- `httprule.requestHostname` (unexported) is the owner of "hostname of `req.Host`".
- `windowcounter` at `v1.0.7` is in the module cache and not in `vendor/` (`vendor/modules.txt` lists `iplookup`, `reclaim`, `simpleredis`, `traefikemulator`). `New(*simpleredis.SimpleRedis, syncRate)` is lazy (no dial); `Take(ctx, key, limit, window)` returns `(allowed, estimated, err)`; window must be whole seconds and at least 1s (`slidingAt`), window start is `now.Unix() / windowSec * windowSec`.
- `simpleredis` binds `CommandTimeout` onto the command context, dials with `DialContext`, and stops retries at whichever deadline comes first (`commands_exec.go` `bindCommandDeadline`, `pool.go`). So a caller deadline bounds dial, send, and retries together.
- Upstream runs the `windowcounter` live tests against `dragonfly:v1.40.2` (`docker-compose.yml` at the tag), the same image the real-stack Pester suite uses, so the buffered-mode `EVAL` flush is exercised on Dragonfly upstream.
- Traefik's plugin config decode has `WeaklyTypedInput` and `StringToSliceHookFunc` only (`knowledge/research/ext_traefik_plugins_config-decode/`). There is no string-to-duration hook, and unknown keys are dropped silently.

## Goals / Non-Goals

**Goals:**

- One new package owns the rate limit; the Bouncer only asks it for a verdict and writes the response with the existing ban and captcha writers.
- A Redis outage costs a request at most a fixed, small delay.
- Settings that this version does not support fail at startup instead of being dropped silently.

**Non-Goals:**

- A shared leg abstraction across `plugin.go` and `Bouncer` (`knowledge/debt/2026-11-20-extract-common-leg-abstraction.md`).
- A backoff gate that skips Redis after repeated failures (`knowledge/debt/2026-11-20-rate-limit-redis-backoff-gate.md`).
- Token bucket, memory store, bucket `captcha` action, `RateLimit-*` headers (debt notes listed in `devstate` `issues.md`).

## Decisions

1. **Package `pkg/ratelimit`, no import of `pkg/configuration`.** `pkg/configuration` must import the bucket authoring type for `Config.RateLimitBuckets`, the same way it imports `httprule.ActionRule`. So `pkg/ratelimit` holds: `BucketRule` and `KeyPart` (authoring), `NewBucketSet` (compile, used by `ValidateParams` and `bouncer.New`), `(*BucketSet).Charge` (evaluation), `Counter` (the one-method interface `Charge` needs), `Client` (the reclaim value), `Open`, `OwnershipKey`, and `RedisSettings`. `Open` takes `RedisSettings` (host, resolved password, database, sync rate) instead of `*configuration.Config`. Alternative: put the authoring type in `pkg/configuration` and the leg in `pkg/ratelimit` importing it — rejected, compile then lives away from the type it validates, unlike `httprule`.
2. **Open-only leg, attached after `bouncer.New`.** `plugin.go` gets `openRateLimit(bindCtx, &config, log, name) (*ratelimit.Client, error)`, called after `openOwned` and before `claimOwned` (implement moved it ahead of `claimOwned`: a taken instance name is then a failure after Open, so the holder release is provable with a real `New`; nothing in the claim reads the counter); it returns nil when `rateLimitEnabled` is false. It calls `reclaim.OpenWithHooks` with `ratelimit.OwnershipKey(name, settings)` (`ratelimit:owner:` + hash of name and settings, the `lapi.OwnershipKey` shape). Create builds `simpleredis.New` then `windowcounter.New`; hooks are `Sleep`/`Wake` of the limiter and a `Close` that closes the limiter then the Redis client (`windowcounter.Limiter.Close` does not close the injected client). After `bouncer.New`, `route.AttachRateLimit(client)` sets a plain field before the handler is returned, so no request can race it. A failed Open fails `New`, and the existing `releaseHolders` defer frees what was opened. Alternative: a new `bouncer.New` parameter — rejected, 109 call sites for one field. Alternative: `atomic.Value` + Watch like the other legs — rejected, nothing publishes this value.
3. **Bouncer holds `ratelimit.Counter`.** Production value is `*ratelimit.Client`, whose `Take` calls `windowcounter.Limiter.Take`. Unit tests in `pkg/ratelimit` and `pkg/bouncer` pass a fake counter. No type assertion on a vendored concrete type is needed anywhere (the Yaegi v0.16 limit recorded in `knowledge/devdocs/std_go_reclaim.md`); the reclaim `create` returns `*ratelimit.Client` and `openRateLimit` asserts this repo's own type.
4. **Catch-all bucket through `httprule`.** Add `httprule.NewWithCatchAll(rules []Rule) (*Set, error)`: same compile as `New`, but a row whose every predicate is any matches every request instead of failing. `compileRule` takes the flag; `New` keeps rejecting. One `Set` holds every bucket, and `Set.Matching` already returns hits in list order. Export the host owner as `httprule.RequestHostname` (callers inside `httprule` renamed) so the `host` key part reads the same text as the `host` predicate.
5. **Bucket authoring shape.** `BucketRule` embeds `httprule.Rule` with `mapstructure:",squash"` (as `ActionRule` does) plus `Name`, `Key []KeyPart`, `Algorithm`, `Requests int`, `Window string`, `Burst int`, `Action`, `Final bool`. `KeyPart` is `From`, `Name`, `Pattern`, `IPv4Prefix int`, `IPv6Prefix int`. `Window` and `Config.RateLimitSyncRate` are strings parsed with `time.ParseDuration` because Traefik's decode has no duration hook. `Algorithm` and `Burst` exist only so `NewBucketSet` can reject `tokenBucket` / a set `burst` loudly; Traefik would otherwise drop them and the operator would get a sliding window without knowing.
6. **Key value owners.** `ip`: `req.IPAddr()` from `clientrequest.Request` (the `GetRemoteIP` result), masked by a new `ip.MaskPrefix(addr net.IP, ipv4Prefix, ipv6Prefix int) net.IP` in `pkg/ip/network.go` (`To4() != nil` selects the IPv4 prefix). `host`: `httprule.RequestHostname`. `path`: `req.URL.Path`. `header`: `req.Header.Get` (canonical name). `cookie`: `req.Cookie(name)`. `query`: `req.URL.Query().Get` — parsed once per `Charge` and only when some bucket has a query part. No part re-parses `RemoteAddr` or forwarded headers.
7. **Redis key and hashing.** `Charge` builds `rl:<middleware name>:<bucket>:<hex(sha256(parts joined by "\x00"))[:16]>`; `windowcounter` appends `:<window start>`. The middleware name comes from `bouncer.New`'s `name`. 64 bits of hash make a collision between two live keys of one bucket negligible, and keep raw tokens out of Redis.
8. **Pipeline step.** `serveRateLimit(rw, req, match) bool` in new `pkg/bouncer/bouncer_serve_ratelimit.go`, called in `ServeHTTP` between `serveLAPI` and `serveAppSec`. It returns false at once when no counter is attached or `match.SkipRateLimit`. Otherwise it runs `Charge` under the step deadline (decision 10), logs each exceeded `log` bucket at INFO, and on a deny calls `b.warnCaptchaSuperseded(req, match)` (a matched captcha rule lost, as for an AppSec ban), sets `Retry-After` (when `rateLimitResponseHeaders`), and calls `handleBanStatusServeHTTP(rw, req, configuration.ReasonRateLimit, headerReasonRateLimit, lapi.OriginPluginRateLimit(bucket), b.rateLimitStatusCode)`. That writer already records the drop, sets the header, `Cache-Control`, status, and the template body rules (same path AppSec uses for its own 429).
9. **`bypassRateLimit` token.** `ActionBypassRateLimit` in `pkg/httprule/action.go`; `actionTokens.skipRateLimit`; `ActionMatch.SkipRateLimit`. In `Fold` the "does this row skip a leg" test and the single-reading path guard include it, so a path rule on an ambiguous path skips no leg, the rate limit included. `bypass` does not set it (open question 1). `ban` stays alone through the existing stem.
10. **Redis outage bound (explore open question "What does a Redis outage cost per request?").** `serveRateLimit` derives `context.WithTimeout(req.Context(), 250ms)` for the whole step, all buckets together. The `simpleredis.Config` used by `Open` is DialTimeout 200ms (library default), CommandTimeout 250ms, PoolSize 8, MaxIdleConns 8, IdleTimeout 30s, default retries. Because `simpleredis` binds the earlier of the command budget and the caller deadline over dial, send, and retries, one request spends at most about 250ms in the step during an outage; a refused connection returns sooner. In buffered mode (default), most hits do not touch Redis at all; Redis is read once per new key per window and probed once per missed sync interval. The first `Take` error stops the walk and applies the failure action; there is no per-bucket retry. Alternatives: decisionstore's 1s command timeout — rejected, it would add up to 1s to every request during an outage; a public timeout knob — rejected, not asked and the budget is an internal bound; a backoff gate — deferred (debt note).
11. **Failure action writers.** `ban` → `banWarnCaptchaRule(rw, req, match, configuration.ReasonRateLimit, headerReasonRateLimitFailure, lapi.OriginPluginRateLimitFailure)`, as `banAppsecFailure` does with `ReasonAPPSEC`. `captcha` → first `b.bypassesCaptcha(req, match)` (continue when true), then `handleCaptchaKindServeHTTP(…, headerReasonRateLimitFailure, origin)`; a cleared gate or widget asset returns false and the request continues, the same as `captchaAppsecFailure`. `passthrough` → return false. Validation reuses `validateFailureAction("RateLimitFailureAction", …, captchaInstanceNameReadyAfterOwnerFill(config))`; `CreateConfig` sets `passthrough`, and `bouncer.New` maps an explicit empty value to `passthrough` through `EffectiveRateLimitFailureAction` (the `EffectiveModsecFailureAction` shape), because `EffectiveFailureAction("")` means `ban`.
12. **Remediation header and origins.** New constants `headerReasonRateLimit = "ratelimit"` and `headerReasonRateLimitFailure = "ratelimit-failure"`. `formatRemediationHeader` keeps one rule — append the encoded third field when the reason carries one — with the third field taken from a small helper: the metrics origin for `lapi`, the origin minus `plugin:ratelimit:` for `ratelimit`. `headerReasonFromOrigin` maps prefix `plugin:ratelimit:` → `ratelimit` and `plugin:ratelimit_failure` → `ratelimit-failure`. `pkg/lapi/client_metrics.go` gains `OriginPluginRateLimitPrefix`, `OriginPluginRateLimit(name)`, and `OriginPluginRateLimitFailure`. Ban template reason `configuration.ReasonRateLimit = "RATE_LIMIT"`.
13. **Retry-After.** `Charge` returns the denying bucket's window; `Retry-After = windowSec - now.Unix() % windowSec` (at least 1), on the same whole-second grid `windowcounter` uses. It is the time to the next window boundary, not a promise that the next request is admitted (the previous window still weighs in). README says so.
14. **Logging.** Over-limit `log` bucket: INFO `crowdsec bouncer rate limit exceeded` with `ip`, `bucket`, `requests`, `window` (the dry run exists to be read). Counter error: DEBUG `serveRateLimit` with `ip` and `error`, never WARN per request (client-driven volume). `Open`: INFO `crowdsec ratelimit instance started` / `closed`, Sleep/Wake at DEBUG, matching the other legs.
15. **Vendoring.** Importing `windowcounter` from a non-test file and running `go mod vendor` adds `vendor/github.com/david-garcia-garcia/traefik-middleware-utilities/windowcounter/` and its line in `vendor/modules.txt`; `go.mod` / `go.sum` stay at `v1.0.7`. No file under `vendor/` is edited by hand (CI re-vendors).
16. **Test bar.** Matches #223/#226: unit tests per package, then real Traefik. Unit: `pkg/httprule` (token, fold, catch-all, host export), `pkg/ip` (mask), `pkg/ratelimit` (compile errors, key parts, order, `final`, `log`, skip on missing value, Retry-After, error stops the walk, Redis key shape) with a fake counter, `pkg/configuration` (every stem), `pkg/bouncer` (pipeline position, deny writer, header, drops, failure actions, `bypassRateLimit`, `bypassCaptcha` on failure captcha, step deadline with a blocking fake counter). Go-layer real Redis: `pkg/ratelimit/zzz_e2e_realredis_test.go` (`//go:build realredis`) against Dragonfly for exact and buffered mode and a dead address. Yaegi: `pkg/ratelimit/zzz_yaegi_test.go` through `pkg/yaegitest` (as `pkg/captcha/zzz_yaegi_provider_test.go`). Real stack: `tests/e2e/real/rate_limit.Tests.ps1` + `config/dynamic/rate-limit.yml` in the `appsec` Pester domain (it already holds the Dragonfly cases).

## Risks / Trade-offs

- [Buffered mode over-admits across replicas, and windowcounter v1.0.7 keeps a stale previous window in buffered mode (upstream PR #63).] → Documented bound in README; `rateLimitSyncRate: 0` for exact counts; bump tracked in `knowledge/debt/2026-11-20-bump-utilities-windowcounter-fixes.md`.
- [Exact mode leaks a key without TTL when the first `EXPIRE` fails (upstream PR #60).] → One leaked key per failure, never reused; same debt note.
- [During a long outage of a blackholed Redis host, every request that needs Redis pays up to 250ms.] → Budget bounds it; `passthrough` keeps traffic flowing; backoff gate follow-up.
- [A `path`-matched bucket can be dodged with an alternate path encoding, as for ban and captcha rules.] → Same debt `knowledge/debt/2026-11-15-ban-captcha-path-rules-ambiguous-path-evasion.md`; a catch-all bucket is not affected; README states it.
- [Docker labels and the Kubernetes CRD may not decode the nested bucket list.] → Only the file provider is proven (real-stack e2e); README shows YAML only and says so.
- [High-cardinality keys (header, query values) create many Redis keys and, in buffered mode, many local window entries.] → Keys expire after two windows in Redis; local entries are dropped at window roll by windowcounter; README advises bounded key sources.
- [`Retry-After` can be shorter than the real wait.] → Documented as time to the window boundary.

## Migration Plan

Additive. Off unless `rateLimitEnabled: true`. Rollback is removing the keys (or the release); Redis keys expire on their own after two windows.
