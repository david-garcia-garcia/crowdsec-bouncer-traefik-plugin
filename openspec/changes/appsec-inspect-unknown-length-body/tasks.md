- [ ] 5.4 New section under `## What you can do`: `### Let streaming request bodies through (gRPC, Connect, long uploads)`. Content: (a) what is blocked and why — a body without `Content-Length` must end or reach `appsecBodyLimit` within `appsecBodyReadTimeoutSeconds`; gRPC/Connect unary calls end and are inspected; client-streaming and bidirectional gRPC, Connect client/bidi streaming, and long-lived uploads without `Content-Length` are blocked after the timeout; WebSockets (GET upgrade) and response streaming (SSE, server-streaming responses) are not affected; (b) YAML examples with `bouncerActionRules` + `bypassAppsec`: by gRPC service path (`path: "^/my\\.package\\.UploadService/"`), by host (`host: "^grpc\\.example\\.com$"`), by header combined with host or path (`headers: {Content-Type: "^application/grpc"}`, Connect `"^application/connect\\+"`), and a long-upload path with `method: "^(POST|PUT)$"`; (c) the trade-off — AppSec does not see matching requests at all (headers, URI, and body), LAPI decisions still apply unless the action is `bypass`; `Content-Type` is sent by the client, so a rule that matches only on it lets any client skip AppSec by sending that header — always scope it with `host` and/or `path`; (d) a longer `appsecBodyReadTimeoutSeconds` is the alternative for slow but finite uploads.
